# 数据浏览器：作品瀑布流兼容方案

把数据浏览器从「一堆 JSON 文件卡片」改成能预览、能播放的作品墙。这版按当前代码能对上的落盘和字段来写，审查里对不上的地方都有明确做法。本文只定方案，不改代码。

## 兼容决定

| 现状 | 这版怎么做 |
| --- | --- |
| 创作者目录的视频没有封面时列表是深色块 | 抖音、小红书有封面时，封面和视频同名放在创作者目录里，作品墙直接用这张图。没有封面的视频仍在进入视口时取 0.1 秒处的画面，同时最多 6 个 |
| CSS 多列会先上下排满，无限滚动时整列重排 | 保留多列。一次只排 24 条，用翻页，不在滚动中往同一列追加 |
| 命令行默认 `jsonl`，文件列表不收录 `.jsonl` | 文件列表补上 `.jsonl`。内容文件进作品墙，评论文件走表格 |
| JSON 是整个数组，不能按字节切片 | 先把这个文件的记录读完，再按页切片。只有这一页做媒体匹配。截图里最大的文件不到 1 MB，整文件解析够用 |
| 一个作品可能有多段视频（正片、`video-durl`、实况） | `video` 是默认播放的那一个，`videos` 列出全部 |
| 创作者目录只在爬取类型为 `creator` 时启用 | 搜索、详情仍到 `media/<作品ID>/` 找封面和图片。作品目录命中后不再扫创作者目录 |
| 贴吧、知乎没有媒体 | 这两个平台的内容文件不进作品墙，继续用表格 |
| 微博记录里没有媒体字段，本地却有文件 | 用 `note_id` 对 `media/<作品ID>/`，能预览、能播放 |
| JSON 昵称已脱敏，`author.txt` 里是原昵称 | 视频落在创作者目录时，作者只显示该目录 `author.txt` 的「昵称」行。账号、签名、主页不返回。对不上目录时用记录里的脱敏昵称 |
| Windows 上现有 `path` 是反斜杠 | 作品接口和媒体接口的相对路径一律用正斜杠 |
| 示例里的 `不使用.jpg` 不是真实文件 | 抖音、小红书创作者目录的封面与视频同名，扩展名是图片。没有这个文件时 `cover` 为 `null` |

## 现在的问题

数据浏览器（`webui/src/components/data/`）只扫描 `data/` 下的 `.json`、`.csv`、`.xlsx`。卡片是文件而不是作品，预览是表格，`data/<平台>/media/` 里的视频和图片不出现在页面上。

弹窗大约 5xl 宽、85vh 高。作品墙打开时加到视口的 90%。

页面默认把结果存成 JSON，命令行默认是 JSONL（`SAVE_DATA_OPTION`）。两种都要能打开。`SAVE_DATA_PATH` 若指向别处，这版和现在的文件列表一样看不到，不另做一套目录。

## 要做到什么

文件列表留下。点内容文件进入该文件的作品墙，点评论文件仍打开表格。

- 瀑布流。图文按图片比例高低错落，视频卡片是 3:4，上面有一帧画面。
- 灯箱里看大图，或用本地文件播放视频，能拖动进度。
- 没有本地文件的作品照样列出，标成「未下载」，不放播放器。
- 贴吧、知乎不进作品墙。

播放只用本地文件。记录里的 `video_download_url`、`cover_url` 一类地址是平台签名直链，过期后打不开，不返回给页面。

## 哪些文件进作品墙

文件名规则是 `{爬取类型}_{种类}_{日期}`，例如 `creator_contents_2026-11-21.json`。路径第二段是平台：`dy/json/...`。

同时满足才出现「作品」按钮：

- 扩展名是 `.json` 或 `.jsonl`
- 种类是 `contents`（文件名按 `_` 拆开，第二段是 `contents`）
- 平台是 `xhs`、`dy`、`ks`、`bili`、`wb`

`creator_comments`、`search_creators` 仍是「预览」。`tieba`、`zhihu` 的内容文件也走「预览」。评论类 JSONL 要能预览：按行读前 100 条，交给现在的表格。现在的预览接口不认 `.jsonl`，这一处要补上，否则评论文件点开是空的。

## 记录怎么收成同一结构

| 平台 | 作品 ID | 标题 | 原文链接 | 本地文件 |
| --- | --- | --- | --- | --- |
| 抖音 `dy` | `aweme_id` | `title`，空则用 `desc` | `aweme_url` | 用作品 ID 去对 |
| 小红书 `xhs` | `note_id` | `title` | `note_url` | 用作品 ID 去对 |
| 快手 `ks` | `video_id` | `title` | `video_url` | 用作品 ID 去对 |
| B 站 `bili` | `video_id` | `title` | `video_url` | 用作品 ID 去对。记录里没有视频直链 |
| 微博 `wb` | `note_id` | `content` 截一段 | `note_url` | 记录里没有封面和视频字段。`media_platform/weibo/media.py` 会把封面、视频、配图下到以微博 ID 命名的目录，用 `note_id` 去对 |

点赞、评论、收藏沿用各平台已有字段，没有就空着。作者见下一节。同一文件里若出现两条相同作品 ID，按文件顺序都显示，这版不去重。

## 本地文件怎么对上

媒体有两种目录，由 `creator_video_layout_enabled()` 决定。只有爬取类型是 `creator` 且保存方案是 `creator` 时，才进创作者目录。搜索和详情永远是作品目录，哪怕页面上选了创作者方案。

**作品目录**

```
data/<平台>/media/<作品ID>/
├── cover.jpg
├── video.mp4          # B 站降级时还有 video-durl.mp4
├── 001.jpg
└── 001_live.mp4
```

**创作者目录**

```
data/<平台>/media/<创作者ID>/
├── author.txt         # 「昵称: …」，另有账号、签名、主页
├── name_index.txt
├── <标题或作品ID>.mp4
└── <标题或作品ID>.jpg  # 仅抖音、小红书，有封面时和视频同名
```

抖音、小红书会多写一张封面，文件名与正片相同。图文没有单独封面时，这张图就是第一张图片。快手、B 站、微博的创作者目录仍然只有视频。`name_index.txt` 一行一条：`作品ID|文件名主干<Tab>实际文件名不含扩展名`。封面那一行的键是 `作品ID|cover`，文件名和 `作品ID|video` 相同。标题会截断、重名会改名，所以不用标题字符串去对文件名。JSON 里的 `creator_hash` 是匿名哈希，也不是创作者目录名。

每个平台建一张对照表，按 `name_index.txt` 和作品目录的修改时间缓存。不要每条记录都把 `media/` 走一遍。

一条作品按这个顺序找，命中就停：

1. `data/<平台>/media/<作品ID>/` 这个目录存在：列出其中的图片和视频。这是搜索、详情，以及创作者模式下仍选了「每个作品一个目录」的文件。
2. 否则查该平台所有 `name_index.txt`，收集以 `作品ID|` 开头的行，拼出创作者目录里的视频。同一文件名如果还有图片，那就是封面。
3. 索引里没有时，只认文件名主体等于作品 ID、等于 `作品ID-durl`、或以 `作品ID_` 开头的视频。这是「用作品 ID 当文件名」的情况。`标题_作品ID` 这种重名文件只认索引；索引丢了就标未下载，不用「文件名以作品 ID 结尾」去猜，短 ID 会撞上别人的标题。

命中创作者目录后，作者名字只取同目录 `author.txt` 里 `昵称:` 后面的文字。账号、签名、主页不放进接口。没有这个文件时，用记录里的 `nickname`（已经脱敏）。

对上之后分成：

- `cover`：作品目录里的 `cover.jpg`，没有则用第一张 `001.jpg`。创作者目录里用和正片同名的图片；没有这个文件就是 `null`。
- `images`：`001.jpg` 这类图片。
- `video`：默认播放。优先主干为 `video` 的文件，没有则用 `video-durl`，再没有就用 `videos` 的第一个。
- `videos`：这个作品对上的全部视频，包含实况 `*_live.mp4` 和 B 站降级文件。每项带相对路径和文件名主干。

## 页面

### 文件列表

保留分类和重新扫描。`.jsonl` 和 `.json` 一样列出，条数按非空行计。内容文件的按钮是「作品」，其余可预览文件仍是「预览」。

### 作品墙

一个文件一墙。顶栏是文件名、作品总数、页码、返回。

每页 24 条。翻页重新请求，不把下一页接在当前列下面。瀑布流用 CSS 多列：

```css
columns: 2;
column-gap: 12px;
@media (min-width: 768px) { columns: 3; }
@media (min-width: 1280px) { columns: 4; }
.card { break-inside: avoid; margin-bottom: 12px; }
```

卡片：

- 有 `cover` 或 `images`：显示第一张本地图，按原图比例，最高 480px，超出部分裁切。灯箱里看完整图片。
- 只有视频：3:4 的区域。卡片进入视口才挂一个静音的 `<video preload="metadata">`，地址加 `#t=0.1`，画出画面后暂停。整个作品墙同时最多 6 个这样的元素，离开视口就移除。
- 本地什么都没有：只显示标题，角标写「未下载」。

卡片下方是标题（最多两行）、作者、点赞数。点卡片打开灯箱，列表里不提供播放控件。

### 灯箱

- 图片：大图，左右切换同一作品的 `images`。
- 视频：原生 `<video controls>`，地址是媒体接口，不带 `#t=`。有多段时可以切换，默认播 `video`。
- 旁边写标题、作者、点赞、评论、收藏、原文链接、本地相对路径。
- 未下载：不放播放器。说明本地没有文件。原文链接仍然可以点。

开发时页面在 5173，媒体地址走现有的 `/api` 代理，不要写死 8080。

## 接口

加在 `api/routers/data.py`。路径解析后必须落在仓库的 `data/` 里。返回的相对路径用正斜杠。

### 文件列表

现有 `GET /api/data/files` 的扩展名加上 `.jsonl`。条数按非空行计算。

### 作品列表

`GET /api/data/works?file=<相对路径>&offset=0&limit=24`

`file` 用文件列表返回的 `path`，例如 `dy/json/creator_contents_2026-11-21.json`。平台不是上面五类、或种类不是 `contents` 时返回 400。

先读出全部记录再切片。`.json` 做一次 `json.loads`。`.jsonl` 按行解析，坏行跳过。只给这一页的作品 ID 查对照表。

```json
{
  "total": 144,
  "file": "dy/json/creator_contents_2026-11-21.json",
  "platform": "dy",
  "items": [
    {
      "id": "7123456789",
      "title": "作品标题",
      "author": "昵称",
      "source_url": "https://www.douyin.com/video/7123456789",
      "stats": { "liked": "1200", "comment": "30", "collected": "10" },
      "downloaded": true,
      "cover": "dy/media/MS4wLjABAAAA/作品标题.jpg",
      "images": [],
      "video": "dy/media/MS4wLjABAAAA/作品标题.mp4",
      "videos": [
        { "path": "dy/media/MS4wLjABAAAA/作品标题.mp4", "stem": "video" }
      ]
    }
  ]
}
```

作品目录命中时，`cover` 形如 `xhs/media/笔记ID/cover.jpg`，`images` 里是 `001.jpg` 这些路径。创作者目录命中时，封面是和视频同名的 `.jpg`。没有的字段用 `null` 或空数组。

### 评论 JSONL 预览

现有 `GET /api/data/files/<路径>?preview=true` 增加 `.jsonl`：按行读到 `limit` 条（默认 100），`total` 为非空行数。内容文件的「作品」按钮不走这个接口。

### 媒体读取

`GET /api/data/media/<相对路径>`

给 `<img>` 和 `<video>` 用。现有下载接口的类型是 `application/octet-stream`，不能拿来播放。

- `.mp4` 用 `video/mp4`，`.jpg` 用 `image/jpeg`，其余图片按扩展名。
- 使用 Starlette 的 `FileResponse`，它支持 Range，视频可以拖进度。
- 只允许图片和视频扩展名（与 `media_downloader/paths.py` 的白名单一致）。`author.txt`、`name_index.txt` 不从这里读。

## 改哪些文件

| 位置 | 改动 |
| --- | --- |
| `api/routers/data.py` | 文件列表纳入 `.jsonl`；作品列表；JSONL 预览；媒体读取；对照表缓存；路径改为正斜杠 |
| `webui/src/lib/api.ts` | 作品列表和媒体地址 |
| `webui/src/components/data/` | 作品墙、灯箱、视口内取帧；内容文件改入口；贴吧和知乎保持表格 |
| `webui/src/components/data/DataExplorerDialog.tsx` | 作品墙打开时把弹窗加大 |
| `webui/src/i18n/locales/*/data.json` | 「作品」「未下载」「返回」「上一页」「下一页」 |
| `tests/` | 两种目录的匹配、命中作品目录后停止、索引缺失时不按标题尾部猜测、微博 ID 对上本地文件、贴吧知乎拒绝、JSONL 按行分页、路径越界和反斜杠 |

不改爬虫，不改落盘格式，不加前端依赖。

## 这版不做

- 把多个 `creator_contents_*.json` 合并成一面墙。
- 用 ffmpeg 抽封面。视口内取一帧就够列表预览。
- 按关键词、平台、是否已下载筛选。
- 同一文件里按作品 ID 去重。
- CSV、Excel、SQLite 的作品墙。
- 无限滚动，以及在卡片上放播放控件。
- 从作品接口返回账号、签名、主页或平台直链。

## 边界

- 播不出来时，先看 `video` 路径在 `data/` 下是否真实存在，再看 `name_index.txt` 有没有这个作品 ID。不要改标题去碰文件名。
- 作品目录和创作者目录里都有同一作品时，以作品目录为准。
- 媒体接口拒绝 `data/` 以外的路径，也拒绝非媒体扩展名。
